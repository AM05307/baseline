## 1. 왜 바꾸나 (요약)

- 지금 가중치는 적중률 기반 최적화(`weighting.compute_weights_significant`)다. 하지만 유의한 신호가 0/14개라서 결과는 사실상
  "균등 초기값"이다(v3 백필 286개 시점 중 근거 있는 것 8개). 전문가 상한(40%) 때문에 그 균등마저 비틀려 있다.
- 같은 원천을 쓰는 신호가 따로 가중치를 받아서, 같은 정보가 점수에 두 번 들어간다(실측 상관은 아래 2.1).
- 위험 단계 기준점(60/80점)은 "가중치 합" 단위라서, 가중치가 바뀌면 단계 판정 빈도도 함께 바뀐다.

## 3. 점수 정의

- 그룹 g가 켜짐 = 그룹 안 신호가 하나라도 켜짐(OR). 같은 원천 신호가 여러 개 켜져도 한 번만 센다.
- **위험 점수 = 켜진 위험 그룹 수 / 값이 있는 위험 그룹 수**(0~1). 값이 없는 그룹(R5 등)은 분모에서 빼고 화면에 따로 표시한다.
  지금 상태: 값이 있는 위험 그룹 4개(R1~R4).
- 가중치는 설정 파일에 고정한다(그룹 균등). **사람이 명시적으로 바꿀 때만** 바뀌고, 바꿀 때는 이유를 weight_history의 live 행으로
  남긴다(algorithm_version 4로 구분 — 기존 1~3과 섞이지 않게).
- 통계 검증(기준률·CI·q값)은 대시보드·스코어카드에 **진단으로만** 계속 보여준다. 가중치를 자동으로 바꾸지 않는다.

## 4. 단계 기준점: 고정 점수 대신 과거 분포의 백분위

### 4.1 방식

1. **기준 설정 구간**(예: 2005-01 ~ 2019-12, 15년)에서 날짜별 위험 점수 분포를 만든다(결정일 정렬, as-of 신호값).
2. 1단계·2단계 기준을 **백분위로 정한다**. 예: 1단계 = 기준 구간 상위 20%에 드는 날, 2단계 = 상위 5%.
   점수가 이산값(켜진 그룹 수)이라 동점이 많으므로, 규칙을 이렇게 정한다:
   "누적 비율이 (1 − q) 이상이 되는 가장 작은 그룹 수"를 기준점으로 하고, 실제 비율(동점 때문에 q와 다를 수 있음)을 함께 기록한다.
3. 정한 기준점(그룹 수)을 **고정**하고, **검증 구간**(2020-01 ~ 최근)에서 다시 맞추지 않은 채 아래를 보고한다.
   - 단계별 날짜 비율이 기준 구간과 얼마나 다른지(차이가 크면 경고)
   - 단계별 이후 5/20/63거래일 수익률: n·평균·중앙값·최대손실(원칙 3·4)
4. 기준점을 바꾸려면 기준 구간을 옮겨 다시 정하고, 그 기록(구간·백분위·결과)을 append-only로 남긴다. 검증 구간 결과를 보고 고르지 않는다.

**대안(walk-forward)**: 매년 초 "그 해 전까지의 전체 기간"으로 기준점을 다시 정하고 그 해에만 쓴다. 과거 대부분 기간에 대해 표본 외 판정이
나온다. 구현이 조금 더 크다.

### 4.2 현재 데이터로 본 모습 (위 2.2 그룹 R1~R4 기준, 참고용)

| 켜진 위험 그룹 수 | 기준 구간 2005~2019 날짜 비율 | 검증 구간 2020~ 날짜 비율 |
|---|---|---|
| 0 | 27.9% | 24.9% |
| 1 | 46.3% | 47.7% |
| 2 | 22.2% | 22.1% |
| 3 | 3.4% | 4.3% |
| 4 | 0.1% | 1.0% |

- 백분위로 정하면: 80백분위 = 2개, 95백분위 = 2개(동점), 97백분위 근처 = 3개. 예를 들어 "1단계 = 2개 이상(기준 구간 25.7%의 날),
  2단계 = 3개 이상(3.5%)"이 된다. 검증 구간에서는 각각 27.4%, 5.3%로 빈도가 비슷하게 유지된다.
- **이후 20거래일 수익률은 그룹 수가 많다고 나빠지지 않았다**(기준 구간 평균: 0개 +4.43% · 1개 +0.53% · 2개 +0.92% · 3개 +4.58%,
  검증 구간: 0개 +3.21% · 1개 +3.87% · 2개 +8.09% · 3개 +3.85%. 3~4개는 표본이 적다). 백분위 기준은 **단계가 얼마나 자주 켜지는지**를
  통제할 뿐이고, 위험을 예측한다는 근거는 아니다. 원칙 1의 예외(기계적 계산 + 근거 동반 표시)는 그대로 충족한다.

## 5. 구현 범위 (그룹 확정 뒤)

- `config/signal_groups.yaml`(그룹 정의) + `analysis/`에 그룹 점수 순수 함수 + 백분위 기준점 계산·검증 스크립트
- `weighting`·`recompute_weights`·백필은 진단용으로 남기고, 단계 판정은 그룹 점수로 바꾼다(전환 전후 비교표 포함)
- 바뀌는 곳: `analysis/risk_score`(판정), 대시보드 위험 카드, what_if·섀도(같은 판정 함수를 쓰므로 자동으로 따라옴)
- 원칙 1 본문의 "60/80점, DEFAULT_RISK_THRESHOLD" 표현이 그룹 수 기준과 맞지 않게 된다 → **원칙 문구 변경이 필요하면 안만 제시하고
  사용자가 확정한다.**
